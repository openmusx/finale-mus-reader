    From F2011-baseline, the punctuation set changed to `#@%&«»` where the last two are
    the guillemets U+00AB and U+00BB. The direct counterpart of
    tests/evidence/F2012/F2012-lyric-punct.mus, and the pair is what shows the tail has two
    layouts rather than one.
    Its record grows from twelve bytes to twenty-four, the six scalars unchanged, and the
    tail is `23 40 25 26 c7 c8` -- six bytes in string order, not three 16-bit code units.
    Finale 2012 writes the same list as one code unit per character. Both containers are
    little-endian, so reading this byte string through the word path would transpose every
    pair of characters.
    The two non-ASCII bytes are what make the code page a measurement rather than an
    assumption. 0xc7 0xc8 is the guillemet pair in Mac Roman and `ÇÈ` in Windows-1252, and
    the companion reads the guillemets, so this Mac-origin document is Mac Roman. The reader
    takes the bank from the document's platform, as it does for a font definition that
    carries no charset of its own; this is the only fixture that tests that choice
    for this field.

Automatic lyric numbering: three saves carrying a binary code

    Finale 2011 adds automatic lyric numbering, and its four fields live in words 6 to 9 of
    selector 58 -- a record that was six words in every earlier era and is twelve from this
    release on. The record therefore states its own layout and needs no version gate.
    Three booleans and an enum cannot be told apart by saves that each change one thing and
    nothing else, because four fields need four distinct signatures. These three saves give
    each field a unique pattern of which files it moves in, so none can be mistaken for
    another: the type moves only in the first, Verses in the first and second, Choruses in the
    first and third, Sections in all three.

F2011-text-inserts.musx
    sha256 b8ff7ce5238bdff0645b4f3d4ceade6653cee670bc48623331868bfe71e6482d
    The third and last of the text-insert fixtures, after F2006 and F2008, and the
    one that closes the binary command table: with it, every command musxdom's
    `EnigmaString.h` documents has a located code. Finale 2009 introduced marking
    categories and Finale 2010 automatic rehearsal marks, so Finale 2011 is the
    earliest available release able to write all four of the commands still
    outstanding.

    Its three expressions carry the font-category commands and fix 0xa4 as
    `^fontTxt`, 0xa5 as `^fontMus` and 0xa6 as `^fontNum`, each named by the
    companion. They are **appended past the inserts** at the top of the table, not
    placed among the style commands at 0x80 to 0x83 where this reader had predicted
    them. That is the second prediction drawn from the shape of the code table to be
    refuted by the first fixture able to test it, after the Finale 2008 one, and the
    two together are why the remaining six free slots are left empty rather than
    filled by inference.

    The three stored arguments are 9, 11 and 11 where the companion writes
    `Times New Roman` and `Engraver Text T`, which settles that a categorized font
    command states a comparator and not a name, exactly as `^fontid` does. The
    reader keeps all three spellings and writes each font under the name its own
    definition carries, falling back to `^fontid` only for a comparator the document
    does not define -- the category a command names being the one thing `^fontid`
    cannot carry.

    Its fourth expression fixes 0xa7 as `^rehearsal` and shows directly that the
    insert takes no argument -- the byte after the code is 0x20, the leading space
    of the literal " Rehearsal", and 0x20 is not a digit byte.

    Two companion differences remain, both intended. The reader drops the character-set
    parenthetical Finale 27 writes after the name, since the font definition states the
    same thing and musxdom reads it only from there. And Finale 27 renames
    `EngraverTextT`, which is what this document stores, to `Engraver Text T`; the
    reader reports the name the document carries.
